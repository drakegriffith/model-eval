\begin{abstract}
\noindent
We report a controlled comparison of two frontier coding agents:
\fable{} (Anthropic, via the \texttt{claude} CLI) and \sol{} ``Sol''
(OpenAI, via the \texttt{codex} CLI). The study comprises 154 runs of a
full-factorial designed experiment (model $\times$ reasoning effort
$\times$ harness), blocked by task, with replicated runs modeled as
Bernoulli trials and seed-interleaved run order. All nine tasks were
verified solvable before any model ran. Both models passed every solo run
(152/152). A per-cell perfect score of $24/24$ carries a 95\% Wilson
interval of $(0.862,\,1.000)$, and the paired head-to-head McNemar test
produced zero discordant pairs. We therefore report no detectable
difference, a claim distinct from and weaker than equivalence. Raising the
reasoning-effort setting changed cost without changing outcomes: the pass
rate was 100\% at every effort level, while \sol{} at high effort consumed
approximately 80\% more output tokens than at low effort. An exact
sign-flip permutation test on per-task median $\log$(total tokens) shows
\fable{} substantially cheaper per solved task ($p = 0.0039$), subject to a
stated caveat on cross-vendor input-token accounting. Two independent model
judges scored all transcripts blind; their scores agreed within one point
on 96\% of 139 dual-judged runs. The principal finding is a ceiling
effect: the suite was too easy to rank the models, and we report that
conclusion rather than a ranking the data do not support. We present the
full design, exact statistics, power analysis, and limitations, and
describe the harder-tier follow-up experiment.
\end{abstract}

% ---------------------------------------------------------------- section 1
\section{Introduction}

Most public comparisons of coding models are anecdotal: one operator, one
prompt, two tools, and a stated preference. Because large-language-model
inference is non-deterministic, a single run measures what happened once
rather than what happens on average, and the average is the quantity that
matters when an organization chooses which tool to adopt. An informal
comparison repeated the next day can reverse its outcome.

Structured public benchmarks face a complementary problem. Frontier models
now cluster near the top of the standard suites, which reduces the suites'
power to discriminate between models, and training-data contamination
allows a model to recall an answer instead of deriving one. Jain et al.\
document both effects for code generation and respond with a
time-segmented benchmark of fresh contest problems~\cite{jain2024livecodebench}.

We therefore ran a designed experiment rather than a leaderboard: identical
tasks and conditions, sufficient replication to separate signal from
sampling noise, exact small-sample statistics, and an explicit statement of
what the sample size can and cannot detect. The design follows standard
design-of-experiments practice in its treatment structure, blocking, and
randomization~\cite{montgomery2017doe}.

Two results follow. The first is a ceiling effect: both models passed every
solo task, so this suite establishes that both clear the tier but cannot
rank them. The second concerns the reasoning-effort setting, which on this
tier produced identical outcomes at materially different token cost, a
pattern consistent with the literature on inefficient
reasoning~\cite{sui2025overthinking,su2025underthinking}.

% ---------------------------------------------------------------- section 2
\section{Experimental design}

\subsection{Treatment structure}

The run matrix is a full-factorial designed experiment:

\begin{itemize}
  \item \textbf{Factors.} Model (\fable{}, \sol{}) $\times$ reasoning effort
        (two to three levels per model) $\times$ harness (bare CLI vs.\ a
        shared agent-instruction harness).
  \item \textbf{Blocking.} Task (eight T1/T2 tasks plus one T3 greenfield
        build). Every configuration sees every task, so task difficulty
        cancels out of all paired comparisons.
  \item \textbf{Replication.} $n=3$ repetitions per cell on T1/T2 tasks and
        $n=2$ on T3. Because inference is non-deterministic, replicated
        runs are required to estimate a pass rate; a single run does not
        constitute a measurement.
  \item \textbf{Randomization.} Run order is seed-interleaved (seed 1337) so
        that time-of-day and API-load drift cannot systematically favor one
        model.
\end{itemize}

The experiment totals 154 official runs: a 120-run sweep~1 (bare
configurations, full effort ladder), a sweep~2 adding harnessed conditions
and the greenfield build, and a small hybrid arm
(Section~\ref{sec:hybrid}).

\subsection{Task suite}

The suite contains nine tasks, each verified solvable before any model ran:

\begin{itemize}
  \item \textbf{Four seeded-bug tasks} containing subtle, deliberately
        introduced defects: an off-by-one error in pagination, a naive
        versus timezone-aware datetime defect, a cache key that omits a
        dimension, and an asynchronous deduplication race condition.
  \item \textbf{Four feature tickets} written in a strict six-section ticket
        format.
  \item \textbf{One greenfield CLI build} (\texttt{splitcost}, a
        cost-splitting tool of approximately 200 lines, with a reference
        implementation).
\end{itemize}

Each task ships with a self-test: the verifier fails on the broken starting
code and passes after the reference patch is applied. All nine self-tests
passed before the experiment began, so any observed failure is attributable
to the model rather than to an unsolvable task.

\subsection{Controlled conditions and blind dual judging}

Conditions were byte-identical across arms: the same harness instruction
files, the same prompts, and the same deterministic \texttt{verify.sh} gate
deciding pass or fail. Every transcript and diff was stripped of
identifying markers and scored blind by two independent judges, one Claude
judge and one GPT judge, on a four-dimension rubric. Dual judging is a
design requirement rather than an optional safeguard: LLM judges carry a
documented self-preference bias~\cite{wataoka2024selfpreference}, and a
single-model judge grading its own model's work embeds a conflict of
interest in the evaluator. Judge agreement is reported as a result in its
own right (Section~\ref{sec:judges}).

% ---------------------------------------------------------------- section 3
\section{Outcome model}

Each run is a Bernoulli trial: pass (\texttt{verify.sh} exit 0) or fail. A
cell's empirical pass rate $\hat p = k/n$ estimates its Bernoulli parameter
$p$; within-cell scatter reflects the Bernoulli variance $p(1-p)$ together
with model non-determinism. All per-cell sample sizes are small
($n \in \{2,\dots,26\}$ per cell; $n=24$ per arm in the primary sweep-1
comparisons), so every test in Section~\ref{sec:methods} is exact. The one
large-sample approximation in this report is the clearly labelled power
search of Section~\ref{sec:power}.

% ---------------------------------------------------------------- section 4
\section{Statistical methods}
\label{sec:methods}

All statistics are computed by a dependency-free reference implementation
(\texttt{runner/stats.py}, Python standard library only) directly from the
raw run and judgment logs. The implementation carries unit self-tests
against known values (Appendix~\ref{app:repro}).

\subsection{Wilson score intervals for per-cell pass rates}

For $k$ successes in $n$ trials with $z = z_{0.975} \approx 1.95996$, the
95\% Wilson score interval~\cite{wilson1927} is
%
\begin{equation}
\frac{\hat p + \dfrac{z^2}{2n}}{1 + \dfrac{z^2}{n}}
\;\pm\;
\frac{z}{1 + \dfrac{z^2}{n}}
\sqrt{\frac{\hat p (1-\hat p)}{n} + \frac{z^2}{4n^2}},
\qquad \hat p = \frac{k}{n}.
\label{eq:wilson}
\end{equation}
%
Unlike the Wald interval
$\hat p \pm z\sqrt{\hat p(1-\hat p)/n}$, the Wilson interval retains correct
coverage at small $n$ and at $\hat p \in \{0, 1\}$, which is the regime of
this experiment, where cells post perfect scores. A perfect $24/24$ is
therefore reported with its interval $(0.862,\,1.000)$ rather than as a bare
``100\%'': the data are consistent with a true failure rate anywhere from
zero to approximately 14\%.

\subsection{McNemar's exact test for paired pass/fail comparisons}

Head-to-head comparisons pair runs by task $\times$ repetition, so the
blocking removes task difficulty from the comparison. With $b$ pairs in
which arm A passed and arm B failed, and $c$ pairs with the reverse
outcome, only the $n_d = b + c$ discordant pairs carry information about a
difference. The exact two-sided McNemar test~\cite{mcnemar1947} is a
binomial test at $\tfrac12$ on the discordant pairs:
%
\begin{equation}
p \;=\; \min\!\left(1,\;
2 \sum_{i=0}^{\min(b,c)} \binom{n_d}{i} \left(\tfrac{1}{2}\right)^{n_d}
\right).
\label{eq:mcnemar}
\end{equation}
%
When $n_d = 0$ the test statistic is undefined, and we report ``no evidence
of difference'' rather than a manufactured $p$-value.

\subsection{Exact sign-flip permutation test on token cost}

We compare token cost per solved task with an exact paired permutation
test~\cite{fisher1935}. For each task $t$ we take the median of
$\log(\text{total tokens})$ over passing runs for each model, form the
paired difference $d_t = \tilde m^{\text{Fable}}_t - \tilde m^{\text{Sol}}_t$,
and enumerate all $2^k$ sign assignments over the $k$ tasks:
%
\begin{equation}
p \;=\; \frac{\#\bigl\{ s \in \{-1,+1\}^k :
\bigl|\sum_{t} s_t\, d_t \bigr| \ge \bigl|\sum_{t} d_t\bigr| \bigr\}}{2^k}.
\label{eq:permutation}
\end{equation}
%
The log transform converts the statistic to a ratio comparison and reduces
the influence of the heavy right tail of token counts; medians over passing
runs keep the comparison on a per-solved-task basis.

\subsection{Power: the minimum detectable effect}
\label{sec:power}

The minimum detectable effect (MDE) is found by a search over the
normal-approximation power of a two-sided two-proportion $z$-test, the one
deliberate approximation in this report. For per-arm size $n$, baseline
$p_1$, alternative $p_2 = p_1 + \delta$, and $\bar p = (p_1 + p_2)/2$,
%
\begin{equation}
\text{power}(\delta)
= \Phi\!\left(
\frac{\sqrt{n}\,\lvert\delta\rvert
      - z_{\alpha/2}\sqrt{2\,\bar p\,(1-\bar p)}}
     {\sqrt{p_1(1-p_1) + p_2(1-p_2)}}
\right),
\label{eq:power}
\end{equation}
%
and the MDE is the smallest $\delta$ with $\text{power}(\delta) \ge 0.80$ at
$\alpha = 0.05$. At $n = 24$ per arm and $p_1 = 0.5$ this gives
$\text{MDE} \approx 36.7$ percentage points. The reporting rule follows: a
gap smaller than the MDE receives a confidence interval, not a verdict. We
report ``no detectable difference'' and do not report equivalence.

\paragraph{Head-to-head.}
Each model's best effort was selected by pass rate with a fewer-tokens
tiebreak (Fable: medium; Sol: low), and the 26 task$\times$rep pairs were
compared with McNemar's exact test (Eq.~\ref{eq:mcnemar}). All 26 pairs
were pass/pass: $b = c = 0$, so the test statistic is undefined and the
comparison carries no evidence of a difference. We conclude \textbf{no
detectable difference} between the models on this suite, a claim
deliberately weaker than equivalence.

\subsection{Effect of the reasoning-effort setting}

The pass rate was 100\% at every effort setting for both models, and every
adjacent-rung McNemar comparison (Fable high vs.\ medium; Sol medium vs.\
low and high vs.\ medium; 24 pairs each) produced zero discordant pairs.
Cost moved instead (Table~\ref{tab:sweep1}, Figure~\ref{fig:effort}):
\fable{} at high effort used 16\% more output tokens than at medium (2{,}008
vs.\ 1{,}736 median), and \sol{} at high effort used 80\% more output tokens
than at low (1{,}966 vs.\ 1{,}095) together with approximately $1.8\times$
the input tokens (174.7k vs.\ 95.2k). On tasks of this tier, higher effort
settings added cost without changing any outcome. This pattern is
consistent with the published work on inefficient reasoning: reasoning
models gauge problem difficulty poorly and produce elaborated output on
easy problems without improving
correctness~\cite{sui2025overthinking,su2025underthinking}.

\subsection{Solution styles}

The two models solve problems in distinct ways. \fable{} iterates: median
6 to 7 turns per task at approximately 59 to 68 seconds of wall-clock time,
alternating between reading, editing, and checking. \sol{} solves in a
single pass: median 1 turn at approximately 26 to 64 seconds, reasoning
internally and emitting one solution. Neither style produced better
outcomes, because both cleared the tier. Turn count is a workflow
signature, not a quality signal.

\subsection{Effect of the harness}

Paired bare-vs-harnessed comparisons at each model's winning effort (14
pairs each) again produced zero discordant pairs: $100\% \to 100\%$. The
harness was designed for longer and less structured work than these tasks.
On this suite it changed token spend (Fable: $-560$ mean tokens; Sol:
$+71{,}624$, driven by its instruction-context handling) but no outcomes.

\paragraph{Caveat: input tokens do not compare across vendors.}
\fable{}'s CLI reports approximately 19.4k median input tokens; \sol{}'s
reports 95k to 175k. This does not indicate that \sol{} reads five to nine
times more code: the two CLIs count context resends and cache reads
differently, so their input-token figures measure different quantities
under the same label (Figure~\ref{fig:input}). Within-model comparisons are
sound because each CLI is self-consistent; cross-model input-token or
dollar comparisons are indicative only, and we do not publish them as firm
claims. The cross-comparable axes are output tokens, turns, and wall-clock
time, and those are the axes this report relies on.

\subsection{The hybrid configuration}
\label{sec:hybrid}

We also tested a hybrid configuration, \fable{} orchestrating \sol{} as the
implementer, on the greenfield task. It was the only configuration that did
not run clean. Across four attempts, two produced planning notes and no
code, and two shipped working solutions of approximately 160 to 176 lines:
\textbf{2 of 4}. The official results file records the two later,
successful attempts; we disclose the two earlier failures here. The rig was
identical across all four attempts, so the most defensible reading is
run-to-run variance in a multi-agent handoff rather than a fixed defect. At
$n=4$ we draw no stronger conclusion; the observation motivates a dedicated
arm in the next experiment.

\subsection{Judge agreement}
\label{sec:judges}

Across 139 dual-judged runs, with each judge's score averaged over its four
rubric axes, the judges show a mean absolute gap of \textbf{0.53} points on
a 0--10 scale, Pearson $r = 0.76$, and \textbf{96\%} of runs within
$\pm 1$ point. On the pilot, the GPT judge scored approximately 0.5 points
higher than the Claude judge on the same diffs, and both judges scored
\sol{}'s code slightly higher. These observations are the self-preference
risk that motivated blind, dual judging~\cite{wataoka2024selfpreference},
and they are the reason we report the disagreement rather than averaging it
away.

\section{Limitations}

\begin{enumerate}
  \item \textbf{Small per-arm samples.} At $n=24$ per arm the design has
        80\% power only for gaps of roughly 36.7 percentage points or more
        at a 50\% baseline (Eq.~\ref{eq:power}). A smaller real difference
        receives a confidence interval, not a verdict.
  \item \textbf{Ceiling effect.} Because both models passed everything, the
        suite cannot rank them; it establishes only that both clear this
        tier. Reading ``154 perfect runs'' as ``the models are identical''
        over-reads the data.
  \item \textbf{Model judges, not humans.} The judging is blind and dual,
        with disagreement reported, but the graders remain automated
        systems with their own biases.
  \item \textbf{One re-run.} A single \fable{} greenfield run hit a
        transient CLI error (2.3\,s, zero tokens) and was re-run. We
        disclose it here.
  \item \textbf{AI-assisted task authoring.} The tasks were verified
        solvable, but their difficulty was mis-calibrated low. That
        miscalibration is the principal finding of the study, not a
        footnote to it.
  \item \textbf{No dollar claims.} Cost figures use list-price placeholders
        over vendor-incomparable token counts, and we do not publish them
        as dollar claims.
  \item \textbf{Long-context asymmetry.} Practitioner reports and published
        long-context research find that model quality degrades as context
        grows large, on the order of 100k tokens~\cite{liu2024lost}. By its
        own CLI's accounting, \sol{} exceeded 100k cumulative input tokens
        on 65 of its 88 runs (median 142k, max 353k); \fable{} peaked at
        19.6k. Two qualifiers apply: the \texttt{codex} CLI counts context
        resends across internal steps, so live context occupancy at any
        moment is not observable from our data; and the bias runs against
        \sol{}, which passed every task regardless. The tie is therefore
        unaffected, but blind-judge quality comparisons carry this
        asymmetry, and we place it on the record.
\end{enumerate}

% ---------------------------------------------------------------- section 7
\section{Future work}

A ceiling result identifies the direction of the next experiment.
Experiment~2 is a hard tier (T4): the same rig, blocking, blind dual
judging, and exact statistics, with task difficulty raised until failures
appear. Failures are the requirement: a gap becomes measurable only once at
least one model begins to miss, and the effort setting can justify its cost
only once a higher setting changes an outcome rather than a token count.

\section{Reproducibility}
\label{app:repro}

Every number in this report is produced by a dependency-free script from
the raw logs:

\begin{quote}
\ttfamily
python3 runner/stats.py -{}-results runner/results/results.jsonl \\
\hspace*{2em} -{}-judgments runner/results/judgments.jsonl
\end{quote}

The script emits the statistical appendix (per-cell Wilson CIs, every
McNemar $2\times2$ table with its exact $p$-value, the token permutation
test, judge agreement, and the power statement) and carries a self-test
mode (\texttt{-{}-selftest}) checking the primitives against known values:
McNemar exact $p(b{=}1, c{=}5) = 0.21875$; Wilson 95\% CI for $8/10 =
(0.4901,\,0.9433)$; sign-flip $p$ for eight positive differences $= 2/256 =
0.0078125$; Pearson $r = 1.0$ on exact linear data. All checks pass.

Judging is blind and dual: transcripts and diffs are stripped of identity
before either judge scores them, and both a Claude judge and a GPT judge
score every run on the same four-dimension rubric.
